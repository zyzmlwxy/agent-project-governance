## 维护规则
1. 创建问题 Issue 时同步创建或更新本文件对应条目；不存在技术结论时写“待调查”，不留误导性结论。
2. 问题原因、影响、状态、处理方案、验收结论发生实质变化时同步更新。
3. 问题已解决后保留记录，不删除；若重新发生，更新原问题或建立关联复发记录，不能抹去原验收结果。
4. 内容应可独立阅读，不要求读者打开 GitHub 才能理解问题的发生、原因和结果。
5. 仅保留当前有效结论与简短处理经过；详细尝试历史、命令和测试证据放在 Issue/PR。
6. 如果摘要与 Issue 不一致，先核验 Issue 和实际证据，再修正摘要；不得用摘要反向覆盖事实。
7. 公开仓库中避免任何个人隐私、秘密、内部网络信息或未经批准公开的业务细节。
