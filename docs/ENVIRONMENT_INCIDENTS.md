# 环境故障与排查经验库（技术记录）

> 用于记录 Agent 执行已授权任务时遇到的环境、连接、权限、工具和部署障碍，便于后续 Agent 先查历史、再排查。此文档不是待修复功能 Issue 列表。允许记录经确认安全的本机文件路径，但严禁提交凭据内容。公开仓库默认使用脱敏路径或占位符。

## 故障记录模板

### ENV-0001：简要标题（示例编号，实际需查重分配）
- **遇到问题的 Agent**：WorkBuddy / ChatGPT / Codex / 其他（记录具体执行者；不是后来阅读者）
- **发生时间及最近验证时间**：带时区的时间；未验证则写 UNKNOWN
- **关联项目任务**：原 Issue/PR/执行报告链接
- **环境标识**：执行机器的安全别名、操作系统及版本、Shell/运行时、工具及版本、工作目录（可公开的部分）
- **目标服务与连接方式**：如 NAS、SSH；不得泄露不必要的私网地址或用户名
- **问题现象**：实际错误、退出码、复现条件、影响范围（日志必须脱敏）
- **原因分析**：CONFIRMED / HYPOTHESIS / UNKNOWN，说明证据
- **尝试过的方法**：每次尝试的操作、实际结果和风险，避免无意义重复
- **最后已知可用的方法**：适用环境、验证时间、前置条件、是否只属历史证据
- **本机文件路径引用**：仅经批准且不泄露身份/环境的路径；例如 `.agent-local/ssh/nas_key`，或 `PRIVATE_KEY_PATH` 指向本机私有配置；不得记录文件内容
- **密钥使用约束**：只说明需要 SSH 身份凭据和引用位置；绝不复制私钥、公钥以外的秘密、密码、Token、密钥指纹关联的敏感信息
- **状态**：OPEN / RESOLVED / BLOCKED / HISTORICAL
- **下次排查步骤**：先核对当前机器/账户/配置是否一致，再做最小、只读、有超时的连接探测
- **后续责任方**：明确 Agent 或项目负责人

## 示例：WorkBuddy 无法连接 NAS（仅示例，非真实故障）

- **遇到问题的 Agent**：WorkBuddy
- **环境**：Windows 执行环境（别名 WB-WIN；版本待核验）
- **现象**：SSH 连接 NAS 失败；错误详情待实际采集
- **可能原因**：密钥文件未被正确引用（未证实）
- **连接方式**：SSH
- **本机密钥位置**：`.agent-local/ssh/nas_key`（示例相对路径，实际路径必须在本机验证）
- **处理结果**：NOT TESTED
- **下次操作**：先确认密钥路径存在且权限正确，再做已授权的只读 SSH 探测；不得生成新密钥或修改 SSH 配置来代替诊断

## 强制维护规则

1. 在当前已授权任务中出现故障后，先搜索本库、关联 Issue/PR、最近执行报告和 `docs/LOCAL_PRIVATE.md`，优先复用已知有效方法；不得把旧的 PASS 当作本轮 PASS。
2. 对新出现的执行故障，在**已有任务的授权记录范围内**及时新增或更新本库的 ENV 编号条目，标明实际遇到问题的 Agent 和环境。记录的是故障经验，不自动创建新的功能 Issue。
3. 相同根因、相同环境的重复故障更新原记录并追加发生时间、尝试及结果；不同环境保留各自差异。不要覆盖原历史。
4. 本机路径可以记录，但先评估仓库可见性。公开仓库不应提交包含真实姓名、用户目录、内部拓扑或敏感项目标识的绝对路径；优先相对路径、变量名、机器别名。若完整绝对路径敏感，只能放在被 Git 忽略的本地私有文件中，Git 记录其相对路径引用。
5. 任何密钥、口令、Token、私有配置内容、原始敏感日志都不得提交 GitHub；不得把 GitHub 文件当作密钥存储。
6. 没有权限写 GitHub 时报告 BLOCKED，并在当前会话给出脱敏待同步记录；不能声称已经保存。
7. 新发现的独立产品缺陷仍遵守 `.agent/ISSUE_DISCOVERY.md` 的用户确认门禁；执行故障记录不代替正式 Issue。
