# APG Template Changelog

## 1.1.0
- Add agent-independent bootstrap and resume protocol.
- Add instance manifest, deterministic next-task selection and adoption guide.
- Preserve existing project files and require verified default-branch readiness.


## 1.0.0
- Initial Issue-first, single-agent, risk-based governance template.

## 1.2.0
- Port problem registration, failure classification, real test evidence and retry escalation from AI-Dev-Bridge-Lite.
- Add project-scoped unique dispatch rounds and Git-backed short instruction handoff for arbitrary agents.
- Keep single-executor default; do not inherit fixed agent roles or automatic execution claims.

## 1.2.1
- Require a plain-language issue register for nontechnical readers, including cause analysis, impact, resolution and verification.
- Add a reusable nontechnical problem template and bootstrap requirements.

## 1.2.2
- Require user confirmation before newly discovered out-of-scope issues are added to GitHub.
- Use temporary 1/2/3/4 choices; allocate permanent unique IDs after confirmation and deduplication.

## 1.2.3
- Prioritize current authorized goal over nonblocking minor or rare edge cases.
- Require transparent reporting of all deferred issues in the temporary numbered discovery list.
- Preserve safety, acceptance and explicit user approval boundaries.

## 1.2.4
- Add Git-backed environment incident memory with agent identity, environment metadata, attempts and verified recovery.
- Permit safe local credential-path references but never credential contents; protect identity-bearing absolute paths in public repositories.
- Require historical incident lookup before repeated troubleshooting and distinguish operational evidence from new Issue approval.

## 1.2.5
- Make the remote Git repository the authoritative development baseline and require commit, push and read-back verification of all shareable deliverables.
- Add explicit local / pushed-unmerged / merged / sync-blocked statuses, plus handoff and project-status fields.
- Clarify that Git synchronization never permits secret disclosure, unapproved writes, or premature new-issue creation.
